## Async (7d): cost per operation

Each figure includes the `ecall` round trip from guest code. *ticket.check*: a guest loop of checks on a pending ticket, net of the same loop without the op. *timer.start* / *cancel*: one guest call doing 16, net of an empty guest call, divided by 16. *Select poll* and *wake round trip* are whole kernel operations (host-to-guest entry included): the first is `poll_task` on a task blocked in `Select2` (two checks); the second is a GPIO event delivered and processed (ticket done, task woken, polled, a new wait armed).

## Async (7d): RAM

- Ticket table entry: **28 B** (Thumb) × 32 tickets = 896 B.
- Inbox entry (driver event, up to a 32-byte packet inline): 36 B × 16 = 576 B; request entry 40 B × 32; the whole shared `Io` (inbox, requests, sent log, counters): **3328 B**.
- Per applet: the `Applet` record is now 64 B (spawned/ready task bits, poll entry, fault flag added).
- Per task slot (guest RAM, in the applet's statics): the future, padded to the slot size, plus 16 B (poll and drop function pointers, size). Kernel side per task: 2 bits (spawned, ready).
- Futures as Rust laid them out (guest, rv32): hello loop 16 B, receive loop 40 B (holds its 32-byte buffer), ticker 52 B, select loop 56 B.
- x86-64 host for comparison: ticket entry 28 B, `Io` 3328 B.

## Bulk statics (7c): cost per access

One read-modify-write (`x += 1`) of a `u32` static in a non-inlined function, called in a loop, minus the same loop calling an empty function. Guest code per access: gp window `mv rd,gp` (the rewritten `auipc`) + `lw` + `addi` + `sw`; bulk `lw rd,slot(gp)` + `lw` + `addi` + `sw`. ## Memory and load time

- Registry entry: **32 B** on Thumb (8 B hash, 8 B name slice into the applet image, the provider, 4 B reserved hook range, enum/Option padding); 48 B on x86-64.
- Whole registry (32 entries + 64-bucket index): **1160 B** on Thumb.
- Per-applet record: **64 B** (16 import slots × 2 B, slot count, code region, gp window and bulk addresses and lengths, gp).
- Loading H, A and B (11 imports, 3 exports): x86 host 3232 per applet, Unicorn (Cortex-M4 cost table) 9092 per applet.
- Host stack per nesting level: **232 B** on Thumb (`run_guest`'s frame; round seven 464 B). Deepest host stack in the whole Unicorn run (includes 7 nested levels): 61284 B.

## ESP32-S3 CRC16 baseline (fixed)

The native baseline on the S3 is now the table-driven `kernels::crc16_table`, the same algorithm the guest image runs (round six used the bitwise loop the Xtensa toolchain emits).
